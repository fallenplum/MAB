# E3有限反馈组合路由开发回放

## 运行环境

本机已验证的资产根目录为 `E:\语言模型组合路由`。运行器会验证原V2 train600 bundle、五折划分与真实组合评分矩阵。Python、NumPy、SciPy、scikit-learn和Matplotlib使用本机已有环境。

完整回放入口如下。

```powershell
& 'E:\语言模型组合路由\.venv\Scripts\python.exe' -B -X utf8 'E:\语言模型组合路由\research\decision_acquisition_e3\public\execute_all.py' --workers 8
```

随机流由折、问题顺序及冻结配置确定，workers控制执行并发。断点续跑会校验每条完整路径的身份、配置、问题流与压缩缓存。未提交的CPU路径重新执行，所有LLM回答继续复用原缓存。

## 执行顺序

1. 先运行数值、权限和一个折的完整机制预检。
2. E3-A诊断反馈响应。
3. B1比较购买哪些当前题评分，B2固定gold时点后比较哪个邻居。
4. J比较完整联合策略。
5. C比较120、240、480题历史规模与三个预测器。
6. D比较行为消融并另作成员复用账本反事实。
7. 20组原题删除后端到端重放，产生主要配对区间及Holm统计。
8. 生成七份报告、完整指标JSON、逐阶段压缩统计和学习曲线。

## 数据与账本

原始前瞻性服务决策、合法评分、完整成本账本和逐题配对数据位于同级 `private` 目录。公共交付包含脱敏聚合统计及代码，原题文本、答案、权重和原始矩阵保存在本地资产目录。

每个正常服务为三个成员与一次聚合。main评分只增加同题gold权限与原始评分，邻居比较复用两个已执行成员。同题gold共用规则适用于全部主方法。

原模型调用wall-time作为来源成本代理。当前评分矩阵未保存GPU kernel时间。缓存回放新增物理LLM调用为0，原始调用费用、策略执行等价费用及本轮CPU开销在报告中分别列出。

## 统计边界

主比较在正式运行前固定为P2、历史240题、每折20道gold。600个原题各作为一次折外题，生成种子和问题顺序均属于重复测量。主统计通过删除原题所有历史、参考及在线角色后完整重放，给出近似删组区间。条件trace区间用于描述性诊断。

本轮为train600开发回放。独立fresh400与sealed200的评分载荷保持封存。后续独立评价按研究结论中的科学条件执行。
